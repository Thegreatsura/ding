What's new in Ding 0.0.9

Toast titles animate under strict Trusted Types policies. The Vue Toaster skips redundant configuration updates.

npm i @yusufceng1z/ding@0.0.9

Title transitions work under Trusted Types

When a new toast replaces a visible one, the old title and description animate out under require-trusted-types-for 'script', including when trusted-types 'none' is set. This applies to React, Svelte, Vue and plain DOM. Issue #46

Vue skips equivalent label updates

Passing a new labels object with the same strings no longer reconfigures the Toaster. Changes to either label, position or theme still apply. PR #47

Ding 0.0.8

Countdowns pause in background tabs

A timed toast shown in the background starts its countdown when you return. If the countdown was already running, it resumes with the time left. This applies to React, Svelte, Vue and plain DOM.

Show the Undo toast, switch to another tab while the line is shrinking, then come back. The line picks up where it left off.

Ding 0.0.7 — safer toast IDs and actions

A late operation should not close a newer message. This release also fixes async Undo, cancelled drags, animation cleanup and two-toaster layout across the built-in renderers.

Old IDs leave newer messages alone Fixed

toast.dismiss(id) still accepts the ID returned by a toast call, but an older call can no longer dismiss the message that took over its slot. Repeated toasts return a usable caller ID; generated IDs avoid collisions with custom IDs.

Open a loading toast, replace it, then try the old caller ID and the visible item's close control.

Start with Loading.

Async actions close on click Fixed

A synchronous action can still return a patch to morph the toast. An async action starts closing the old toast when clicked; its resolved value is not treated as a patch. Show its result as another toast, or use toast.promise() to morph a loading toast to its result. An action that opens a new toast no longer accidentally closes it.

Drag and animation cleanup Fixed

pointercancel now resets a drag instead of flinging the toast. Unmounting stops its animation work, and two mounted Toasters both receive layout updates in the same frame. Escape and Alt+T keep working when one of two mounted Toasters unmounts, including React.

Upgrading a custom renderer Changed

toast.dismiss(id) and toast.dismiss() remain available. If your custom close button used toast.dismiss(item.id), switch it to toast.close(item.id): the visible item's physical ID may differ from its newest caller ID. The built-in React, Svelte, Vue and plain DOM renderers are already updated. See the API reference. Thanks to Jens for the close(id) distinction and repeat-ID regression.

Ding 0.0.6 — held toasts

Errors no longer get buried. One default changed, and one option brought the old behavior back.

An error with a Retry button used to be replaced by the next toast, so it could be missed. Now it stays on screen. The demos below still run the library.

A toast that waits for you keeps its place Fixed

A toast is held when it stays until dismissed: an error, a toast with a button, or one with duration: 0. Before, any new toast morphed the held one away. Now the held toast stays and quick toasts appear next to it.

Show the error first, then the other two. The error stays.

Choose how toasts share the screen New

The new held option of toast.configure decides what happens when a toast arrives while a held toast is on screen.

toast.configure({ held: 'list' }); // list, queue or replace
  • list is the default. The held toast keeps its place and quick toasts appear next to it. A new held toast takes over the quick one.
  • queue makes new toasts wait in order. They show one after another once the held toast is gone.
  • replace is how 0.0.5 behaved. A new toast morphs the one on screen, held or not.

Pick a mode, then run the three toasts above again.

Upgrading Changed

The default changed from replace to list. If a held toast was replaced before, it now stays until the user dismisses it. To keep the old behavior, set it once:

toast.configure({ held: 'replace' });

In plain DOM, mountToaster({ held: 'replace' }) does the same. A loading toast is not held, because it is about to turn into its result. See Held toasts in the docs.
